# ADR-008: `DEVELOPER_GUIDE.md` 手戻り再スタートブランチ表の破損表記の修正

> ✅ **本ADRは実装済み**（2026-07-08）。No60（機能ID採番スキーム変更）の実装レビュー中に発見した、No60とは無関係の既存の破損表記。

## 目的（この対応で達成したいこと）

- **Why（なぜ対応するか）**: `DEVELOPER_GUIDE.md`「6.9 手戻りフロー」§「再スタートの issue・ブランチ（`-sp-{m}`）」の表に、意味不明な文字列が2箇所（PG-Plan/PT-Plan行・SS/PG/PT行）含まれており、手戻り再スタート時にAI・人間のいずれが読んでも正しいブランチ名を導出できない状態になっている。
- **What（何を対応するか）**: 破損した2行を、`.claude/rules/product-rules.md`「手戻り統一ワークフロー」節が定める正しいブランチ命名規則（正典）に合わせて修正する。
- **How（どう対応するか）**: `product-rules.md`の該当記述（実施工程＝`feature/{案件キー}-{ss|pg|pt}-{機能ID}-sp-{手戻りID}`、計画・上流工程＝`feature/{案件キー}-{工程}-sp-{手戻りID}`）と、表の1行目（SA/UI/SS-Plan行。破損していない参照可能な行）の記法パターンに揃えて2行を書き換える。

## 背景

### ①状況

No60（機能ID採番スキーム変更）の実装レビュー中に、`DEVELOPER_GUIDE.md`の同種の表記ミス（プレースホルダーと具体例の連結）を横展開で確認していたところ、「6.9 手戻りフロー」§「再スタートの issue・ブランチ」の表に、No60とは無関係の別の破損を発見した。

### ②課題・問題

対象の表（現状）:

```
| 区分 | リポ | issue | ブランチ |
|---|---|---|---|
| 上流・計画（SA/UI/SS-Plan） | 案件リポ | 新規 | `feature/{案件キー}-{sa\|ui\|ssplan}-sp-{m}` |
| 計画（PG-Plan/PT-Plan） | スタックリポ | 新規 | `feature/{案件キー}-{{ss|pg|pt}-{機能ID}plan\|ptplan}-sp-{m}` |
| 実施（SS/PG/PT） | スタックリポ | **既存改修=Reopen／追加=新規** | `feature/{案件キー}-{ss|pg|pt}-{機能ID}\|{ss|pg|pt}-{機能ID}\|{ss|pg|pt}-{機能ID}-sp-{m}` |
```

1行目（SA/UI/SS-Plan）は正しく`{sa|ui|ssplan}`という選択記法になっているが、以下2行に破損がある。

- **2行目（PG-Plan/PT-Plan）**: `{{ss|pg|pt}-{機能ID}plan\|ptplan}`という文字列は、実施工程用の記法（`{ss|pg|pt}-{機能ID}`）の断片と、計画工程の末尾（`plan`）・`ptplan`が無関係に混在しており、文法的に成立していない。
- **3行目（SS/PG/PT）**: `{ss|pg|pt}-{機能ID}\|{ss|pg|pt}-{機能ID}\|{ss|pg|pt}-{機能ID}-sp-{m}`という文字列は、同一の記法`{ss|pg|pt}-{機能ID}`が`\|`（エスケープされたパイプ）で3回連結されており、`-sp-{m}`が末尾に1回しか付いていない（本来は1回の記法で足りるはずである）。

`.claude/rules/product-rules.md`の該当記述（正典）を確認したところ、以下の通り明記されている。

```
- 実施工程（SS/PG/PT）: `feature/{案件キー}-{ss|pg|pt}-{機能ID}-sp-{手戻りID}`（例: `-ss-F001-sp-001`）
- 計画・上流工程（SA/UI/SS-Plan/PG-Plan/PT-Plan）: `feature/{案件キー}-{工程}-sp-{手戻りID}`（例: `-sa-sp-001`・`-pgplan-sp-001`）
```

`product-rules.md`はPG-Plan/PT-PlanをSA/UI/SS-Planと同じ「計画・上流工程」1グループとして扱う一方、`DEVELOPER_GUIDE.md`の表は「リポ」列（案件リポ vs スタックリポ）で行を分けているため、PG-Plan/PT-Plan単独の行が必要という表の構成自体は理由がある。ただし、その行の値が破損している。

`git show origin/main:DEVELOPER_GUIDE.md`で確認した結果、この破損はNo60着手前から存在していたことを確認済みである（No60は同じファイルの別箇所〔L237の`{機能ID}-bs-001`〕のみを修正しており、本箇所は対象にしていない）。破損の発生時期・原因（過去の一括置換ミスの可能性が高いが特定はできない）は本ADRの範囲では追跡していない。

### ③制約

- 表の構成（リポ列で行を分ける構成）自体は変更しない。1行目（SA/UI/SS-Plan）の記法パターンは正しいため変更しない。
- `product-rules.md`の記述自体は変更しない（正典として参照するのみ）。

## 決定事項

`DEVELOPER_GUIDE.md`の該当表の2・3行目を、`product-rules.md`の正典表記に合わせて以下に修正する。

```
| 計画（PG-Plan/PT-Plan） | スタックリポ | 新規 | `feature/{案件キー}-{pgplan\|ptplan}-sp-{m}` |
| 実施（SS/PG/PT） | スタックリポ | **既存改修=Reopen／追加=新規** | `feature/{案件キー}-{ss|pg|pt}-{機能ID}-sp-{m}` |
```

## 理由

- `product-rules.md`が正典であり（`DEVELOPER_GUIDE.md`は日常開発フローの解説であり規則そのものの正本ではない）、表現の齟齬がある場合は正典に揃える。
- 1行目（SA/UI/SS-Plan）の`{sa|ui|ssplan}`という記法パターンと構造を揃えることで、3行間の一貫性を確保する。

## 影響

- `DEVELOPER_GUIDE.md`の1ファイル・2セルのみの変更。他ファイルへの影響はない（ドキュメントの記述内容のみで、スキル・フック等のコード動作には影響しない）。
- 手戻り再スタート時にこの表を参照する人間・AIが、正しいブランチ名を導出できるようになる。
