# 将来削除予定の暫定マーカー

このドキュメントは、本プロダクトに現時点で残されている **サンプル的・暫定的な表現** を一覧化したものです。
方針が決まり次第、対応する削除コマンドで一括除去できるように、マーカーを統一しています。

---

## マーカー 1: `BUILD_TBD.md`

各テンプレートパッケージに置いてあるビルドツール未確定のプレースホルダー。
Maven / Gradle のいずれかが確定したら、`pom.xml` または `build.gradle` に置き換えて削除。

### 出現箇所の確認

```bash
find _templates -name 'BUILD_TBD.md'
```

### 削除タイミング

ビルドツール選定の意思決定が完了し、テンプレに具体的なビルドファイルが配置できるようになった時点。

---

## マーカー 2: `← TBD` コメント

テンプレ CLAUDE.md 内で値が未確定のフィールドに付けてあるマーカー。

例:
```markdown
- Springer バージョン: **3** （Spring Boot 4 系）  ← TBD
- ベースパッケージ: jp.co.example.{product}.bs   ← TBD
```

### 出現箇所の確認

```bash
grep -rn "← TBD" _templates/
```

### 削除タイミング

各テンプレを実プロダクト用にコピーした際、値を確定させてから `← TBD` を削除。

---

## ローテーション対象（削除ではなくアーカイブ）

### 作業ログ `docs/changelog/work-logs/{YYYY-MM-DD}.md`

`.claude/hooks/log_work.py` により日々追加されるため、長期運用では肥大化します。

**自動アーカイブ（既に組み込み済み）**:
- フック実行時に **前月以前** のデイリーログを `docs/changelog/work-logs/archive/{YYYY-MM}/` に **月次で自動移動** します
- 当月分は `work-logs/` 直下に残ったまま日々追記されます
- 冪等処理のため再実行に副作用なし

**二次整理（任意・将来の検討事項）**:

数年分の `archive/` が肥大化してきたら、以下のいずれかで集約してください:
- 年単位ディレクトリへの再編: `archive/{YYYY}/` 配下に月別を入れる二段構造
- 月次集約ファイル: `archive/{YYYY-MM}-summary.md` に集計して個別ファイルを削除
- 長期保管庫への移送: 監査要件に応じた別ストレージへ

監査要件・社内規定がある場合はそちらを優先してください。

---

## 運用ルール

- 新しい暫定マーカーを追加する際はこのファイルにも登録すること
- マーカーを削除する際は、削除後に `grep` でゼロ件を確認すること
- 削除作業の CHANGELOG への記録を忘れないこと
