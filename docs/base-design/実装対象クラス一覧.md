## フロント・バック間の責務分担

| 分担項目 | frontend | backend |
|---|---|---|
| 入力バリデーション | Zod スキーマ（各 `*Schema.ts`）で必須・文字種（数字）・桁数（固定長・最大長）チェックを行う（`react-hook-form` の `onSubmit`/`onTouch` 契機） | bs 未着手のため本UI issueでは対象外。SS工程で Bean Validation 等による最終防衛線チェックを確定する（参考: `Web_API_IF定義書_bs-001〜009.md` の400 Bad Requestレスポンス構造） |
| エラーメッセージ | `ErrorMessage` コンポーネントによるフォームフィールド直下のインライン表示、および `useErrorHandling` によるAPIエラーのトースト表示（`errorCode`・`detail[].ValidationMessage` を判定） | bs 未着手のため本UI issueでは対象外。`RestErrorInfo`（`errorCode`/`message`/`detail[]`）形式でのエラー返却は SS 工程で確定する |
| 認証状態の保持 | `AuthUserContext` でユーザー情報をローカルストレージ（キー `auth`）に保持し、Cookie（`withCredentials: true`）でセッションを維持する | bs 未着手のため本UI issueでは対象外 |
| 認可（権限）制御 | メニュー画面のボタン表示制御・管理者用画面のルートガード（`PrivateRoute` 相当）はクライアント側の抑止的制御のみ | bs 未着手のため本UI issueでは対象外。実際の認可判定はAPI側（bs）で行う想定（`docs/requirements/要件定義_R003.md`・`_R007.md` の非機能要件） |
