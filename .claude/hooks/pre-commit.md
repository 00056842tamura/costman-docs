# フック定義: コミット前チェック

## トリガー
git commit 実行前

## チェック項目

### 1. コード品質

#### Reacter（frontend/ を変更した場合）
- [ ] `npm run lint` が通ること（ESLint エラーなし）
- [ ] TypeScript 型エラーがないこと（`npm run build` でビルドが通ること）
- [ ] `console.log` が残っていないこと
- [ ] `debugger` が残っていないこと
- [ ] `TODO` コメントが残っていないこと

#### Springer（bs/ / us-api/ 等を変更した場合）
- [ ] `check_java.py` の警告がゼロであること
- [ ] Lint エラー・コンパイルエラーがないこと
- [ ] `TODO` コメントが残っていないこと

### 2. セキュリティ
- [ ] ハードコードされた API キー・パスワードがないこと
- [ ] `.env` ファイルがステージングされていないこと
- [ ] `VITE_` 以外のシークレット情報が `frontend/src/` に含まれていないこと

### 3. テスト

#### Reacter（frontend/ を変更した場合）
- [ ] `npm test` が全件パスすること
- [ ] テストカバレッジが規定値以上であること

#### Springer（bs/ / us-api/ 等を変更した場合）
- [ ] `mvn test`（または `./gradlew test`）が `BUILD SUCCESS` であること
- [ ] テストカバレッジが規定値以上であること

### 4. コミットメッセージ形式
```
feat({案件キー}-{工程}): {変更内容の簡潔な説明}
```

## 問題があった場合
チェックに引っかかった項目を列挙し、コミットを中断する。
修正後に再度コミットを実行する。
