# 開発プロセスレビュースキル

開発ワークフロー全体の **インプット・プロセス・アウトプットの連鎖が正しく繋がっているか** を検査する。

## 設計原則（動的チェック）

このスキルは特定のスキル名・テンプレート名・Step 番号をハードコードしない。
代わりに以下の **4 つの真実の源泉** を動的に読み込み、ペア間の不整合を検出する:

| 真実の源泉 | 役割 |
|---|---|
| `README.md` §5 ステップ別フロー早見表 | ワークフロー全体の正規定義（各 Step の入力・スキル・出力） |
| `docs/templates/README.md` テンプレート一覧表 | テンプレートと生成タイミング・担当スキルの正規定義 |
| `.claude/skills/*/SKILL.md`（全スキル） | 各スキルの I/O 仕様の正規定義 |
| `.claude/orchestrators/*.md`（全オーケストレーター） | 壁打ちフローの正規定義 |

スキル・テンプレート・ステップが追加・変更された場合、これら源泉ドキュメントを更新することで、次回の `/process-review` 実行時に自動的に検査対象となる。

`/config-review` との違い:

| スキル | 対象 | 検査観点 |
|---|---|---|
| `/config-review` | プロジェクト構成ファイル | スキル数・バージョン・フック設定等の静的な整合性 |
| `/process-review` | 開発ワークフロー | スキル/オーケストレーターの読み書き連鎖・タイミングの動的な整合性 |

## 入力形式

> ⚠️ **実行前に `/clear` でコンテキストをクリアしてから起動すること。**

```
/process-review
```

引数なし。プロダクトルートから起動すること。

---

## 実行手順

### Step 0: コンテキストクリアの確認

会話が既に長くなっている場合は処理を中断し、ユーザーに `/clear` 後の再実行を促す。

---

### Step 1: 真実の源泉を動的収集

**すべて Glob または Read で実態から収集する（ハードコードしない）。**

1. `README.md` §5「ステップ別フロー早見表」テーブルを読み込む
   - 各行から **Step 番号・STEP 名・使用スキル/ツール・成果物** を抽出する
   - これが全チェックの基準となるワークフロー定義

2. `docs/templates/README.md`「テンプレート一覧とワークフロー対応」テーブルを読み込む
   - 各行から **テンプレート名・生成先・ファイル管理区分・初回作成タイミング・最終更新タイミング** を抽出する

3. `.claude/skills/` 配下の全 `SKILL.md` を Glob で収集し、各ファイルを読み込む
   - スキル名は YAML フロントマターの `name:` フィールドから取得する
   - 各 SKILL.md から **入力ファイル読み込みセクション** と **出力ファイル生成セクション** を抽出する
   - 「一覧系（差分追記）」「機能別（新規作成/上書き更新）」の更新ルールが明示されているかも確認する

4. `.claude/orchestrators/` 配下の全 `.md` を Glob で収集し、各ファイルを読み込む
   - 各オーケストレーターから **入力ドキュメントの読み込みリスト** を抽出する

5. `docs/templates/` 配下の全 `.md` ファイルパスを Glob で収集する（README との照合用）

6. `specs/templates/` 配下の全ファイルパスを Glob で収集する（`/issue-init` との照合用）

---

### Step 2: 5 観点の整合性チェック

以下の全チェックは Step 1 で収集した実態を元に動的に実施する。特定の名称・件数・パスを前提にしない。

---

#### チェック A: README.md ↔ 各スキル SKILL.md の I/O 整合性

**目的:** ワークフロー定義（README.md §5 表）と各スキルの実装定義（SKILL.md）が一致しているかを確認する。

**手順:**

1. Step 1 で抽出したワークフロー表から、スキルを呼び出す全行を抽出する
2. 各行について、対応するスキルの SKILL.md を読み込み以下を確認する:

   **入力整合性**: README.md 表の「人の指示（Claude への入力）」に記載された入力ファイル・前提条件が、SKILL.md の「必要ドキュメントの読み込み」セクションに含まれているか

   **出力整合性**: README.md 表の「成果物」列に記載されたファイル・ドキュメントが、SKILL.md の「ファイル書き込み」または「生成対象」セクションに含まれているか

   **次ステップ連鎖**: SKILL.md の完了報告「次のアクション」が README.md の次 Step と一致しているか

3. 逆方向チェック: SKILL.md に記載された出力が README.md の当該 Step の「成果物」に含まれているか

**検出すべき問題例:**
- README.md の Step 表には「成果物: テスト仕様書」とあるが、対応スキルの SKILL.md にその記述がない
- SKILL.md の完了報告で案内する「次のアクション」が古いスキル名になっている
- ワークフロー表に列挙されているスキルが `.claude/skills/` に存在しない

---

#### チェック B: docs/templates/README.md ↔ 各スキル SKILL.md の出力整合性

**目的:** テンプレート一覧で「このスキルが生成する」と定義されたテンプレートが、実際にそのスキルの SKILL.md に出力として記述されているかを確認する。

**手順:**

1. Step 1 で抽出したテンプレート一覧表の全行について以下を確認する:

   **「初回作成タイミング」のスキルチェック**: 表に記載されたスキル名（例: `/basic-design-gen`）の SKILL.md に、そのテンプレートに対応するファイル（例: `シーケンス図_{機能ID}.md`）の生成ロジックが含まれているか

   **「最終更新タイミング」のスキルチェック**: 更新担当スキルの SKILL.md にも同様の更新ロジックが含まれているか

2. 逆方向チェック: 各スキルの SKILL.md に記載された出力ファイルが、テンプレート一覧表の「生成先」として記載されているか

3. **更新ルール整合性チェック**: テンプレート一覧表の「ファイル管理区分」と、対応スキルの SKILL.md に記述された更新ルールが一致しているか:
   - `共通1ファイル` / `スタック別1ファイル` → スキル内に「差分追記・既存記述は削除しない」ロジックがあるか
   - `スタック別・機能別` → スキル内に「新規機能: 新規作成、既存機能修正: 上書き更新」ロジックがあるか

4. `docs/templates/` の実ファイル一覧と `docs/templates/README.md` テーブルを照合し、テンプレートファイルが表に未記載の場合を検出する

**検出すべき問題例:**
- テンプレート一覧表に「Step 2.5 `/basic-design-gen`（AI 生成）」とあるが、`basic-design-gen` の SKILL.md にそのファイル生成が記述されていない
- `機能別` 区分のテンプレートだが、対応スキルに「差分追記」と書かれており「上書き更新」の記述がない
- `docs/templates/` に実ファイルが存在するが README の表に未記載

---

#### チェック C: スキル間の I-P-O 連鎖整合性（ステップをまたいだ繋がり）

**目的:** あるスキルの出力が、次のスキルの入力として適切に参照されているかを確認する。

**手順:**

1. Step 1 で抽出したワークフロー表から「各ステップのスキルと成果物」のシーケンスを構築する
2. 各 Step の成果物が、その次に実行されるスキルの入力として参照されているかを SKILL.md 間で確認する

   ```
   Step N の成果物（README.md §5 表から動的取得）
     ↓
   Step N+1 のスキル SKILL.md の「必要ドキュメントの読み込み」に含まれているか？
   ```

3. 特に以下のパターンを確認する:
   - あるスキルが生成したファイルを「後続スキルが必ず読む」と記述されていない
   - 完了報告の「次のアクション」が実際の次 Step のスキル名・形式と一致していない

**動的対象**: ワークフロー表に追加されたすべての新しいステップ・スキルが自動的に対象となる。

---

#### チェック D: オーケストレーターの入力整合性

**目的:** 各オーケストレーターが処理に必要なドキュメントを読み込んでいるかを確認する。

**手順:**

1. Step 1 で収集した全オーケストレーターに対して以下を実施する:
2. オーケストレーターが使用される README.md のステップを特定する
3. そのステップで利用可能なドキュメント（前ステップまでの成果物）と、オーケストレーターが実際に読み込むドキュメントを照合する:
   - 前ステップの成果物に含まれるドキュメントを読み込んでいるか
   - 存在しないファイルパス（`docs/test/results/latest.md` 等）を参照していないか
   - 新規プロダクト時に既存ドキュメント（`docs/requirements/` 等）を条件付きで読み込んでいるか

**動的対象**: `.claude/orchestrators/` に追加された新しいオーケストレーターが自動的に対象となる。

---

#### チェック E: specs/templates ↔ /issue-init 整合性

**目的:** `specs/templates/` に追加されたテンプレートが `/issue-init` でコピーされるよう定義されているかを確認する。

**手順:**

1. `specs/templates/` 配下の全ファイルを列挙する
2. `issue-init` SKILL.md の「テンプレートファイルのコピー」テーブルと照合する
3. 以下の除外ルールを適用した上で、漏れを検出する:
   - `implementation-plan.md` — `/issue-plan` が生成するため除外が正しい
   - `design/phase-detailed/` 配下 — `/detailed-design-gen` が生成するため除外が正しい
   - それ以外で未記載のファイルは問題として報告する

---

### Step 3: 問題の修正

検出した問題を以下の方針で **その場で修正** する。

| 問題の種類 | 対応 |
|---|---|
| README.md §5 表の成果物記載と SKILL.md の出力が不一致 | README.md の表記を SKILL.md に合わせて修正する |
| SKILL.md の完了報告「次のアクション」が旧スキル名・旧形式 | SKILL.md の完了報告を修正する |
| テンプレート一覧表のスキル名と実 SKILL.md の出力が不一致 | docs/templates/README.md のタイミング列を修正する |
| 一覧系/機能別の更新ルールがスキルと README で不一致 | どちらが正しいかを README の「ファイル管理区分」を基準に判定して修正する |
| オーケストレーターが存在しないファイルを参照 | 参照を削除または存在するファイルパスに修正する |
| specs/templates のテンプレートが `/issue-init` に未記載 | コピーテーブルに追記する |
| ファイルが存在しない（定義はあるが実ファイルが無い） | **修正せず** ユーザーに報告する |

> ⚠️ **スキル・オーケストレーターの業務処理ロジック（壁打ちの質問内容・設計書の生成詳細）は変更しない。** I-P-O の接続部分（入力リスト・出力リスト・次アクション案内・タイミング記述）のみ修正する。

---

問題が 0 件の場合は `✅ すべてのチェックをパスしました` のみ出力する。

---

## 実行タイミング

以下のいずれかが発生したときに実行する:

- `docs/templates/` または `specs/templates/` にテンプレートを追加・変更した
- `.claude/skills/` にスキルを追加・変更した
- `.claude/orchestrators/` を変更した
- `README.md` §5 開発フローを変更した
- `docs/templates/README.md` テンプレート一覧を変更した

---

## 制約

- ✅ 検出した問題は可能な限りその場で修正する
- ✅ 修正後は `README.md` の改訂履歴に追記する
  - 改訂履歴の日付は、スキル実行日が土曜・日曜の場合は直前の金曜日の日付を使用する
- 🚫 スキル・オーケストレーターの業務処理ロジックは変更しない（I-P-O 接続部分のみ対象）
- 🚫 `docs/` 配下の実際の設計書ファイルは変更しない（定義ファイルとドキュメントのみ対象）
- ✅ 特定のスキル名・テンプレート名・Step 番号をこのスキル内にハードコードしない（すべて動的収集）
