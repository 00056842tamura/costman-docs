## 入出力（工程6 PG）

- **入力（設計書）**: `docs/base-design/機能概要_{機能ID}.md`・`Web_API_IF定義書_{機能ID}.md`（基本設計）＋ `specs/{案件キー}/detail-design/frontend/{issue_id}_{機能ID}/frontend.md`（詳細設計WB）＋ **`frontend/docs/detail-design/コンポーネント仕様書_{機能ID}.md`**・**`画面アクション遷移図_{機能ID}.md`**（SS 工程生成済み）。プロンプト指定がある場合はそれも併用。
  - **`画面アクション遷移図_{機能ID}.md`は、アクション（ボタン押下等）ごとの画面表示の変化・遷移先を1枚の図で俯瞰できる資料。ハンドラー実装（state更新・画面遷移の呼び出し）の実装順序・分岐を組み立てる際に必ず参照すること**（コンポーネント仕様書の「画面遷移」「アクション定義」表と同じ内容を可視化したもの）。
- **出力（コード）**: `frontend/src/` へ直接（直接編集モデル）。
- ⚠️ **コンポーネント仕様書・画面アクション遷移図は SS 工程（`/detailed-design-gen`）で `frontend/docs/detail-design/` に生成済み**。実装の指針となるドキュメントは詳細設計で担保されるべきであり、本スキルでは生成しない。
- 作業場所は **スタックリポ（frontend）**。レビューは `/reacter-code-review`（レポートは specs/issue 添付）。

## プログラミングルール

- reacterプログラミングルール: `.claude/rules/reacter-*.md` のルールファイルを参照すること
- **インデックス表を見ただけでルール理解とみなすことは禁止。** ガイドファイルを Read ツールで実際に読むこと。
- **ガイドファイルの Read、コード生成はサブエージェントが行うこと。** メインエージェントはサブエージェントへの指示プロンプトに「インデックス表を見るだけではなく、担当作業に関連するガイドファイルを Read してからコードを生成すること」を明示すること。

## 手順

1. **[メインエージェント]** 設計書を読み込み、コード生成に必要な情報を抽出する。
2. **[メインエージェント]** 共通化のため、以下の観点で共通要素を抽出する。
     - ユーティリティ: 日付操作、文字列整形など
     - hooks: エラーハンドリング、クリア処理など
     - UIコンポーネント: 共通ヘッダー、ダイアログなど
     - グローバル変数: reactのコンテキストなど
     - 型定義: TypeScriptの型定義
3. **[メインエージェント]** 計画を立てる。サブエージェントの役割分担を決める。メインエージェントはオーケストレーターとなる。サブエージェントは最大5多重度とする。
4. **[メインエージェント]** サブエージェントを起動し、ガイドファイルを Read させ、コード生成を開始させる。
5. ひととおりのコードが完成したら、共通化の見直しなどのリファクタリングを、サブエージェントを起動して開始させる。リファクタリングの指示プロンプトには以下を含めること。
     - リファクタリングの目的（例: コンポーネントや関数の共通化、コードの可読性向上など）
6. コード生成・修正完了後は、`reacter-*.md` ルールに従ってセルフレビューを実施すること。

## 出力時の注意

- コードの改善/修正・生成後は、本ルール群に従ってセルフレビューを実施すること。
- 出力（説明・コメント）には、適用したルールの根拠ガイドのファイルパスを含めること。
