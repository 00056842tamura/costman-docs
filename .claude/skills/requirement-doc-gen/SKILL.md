# 要件定義書群生成スキル（工程1 SA・2 段階方式の生成段）

`issue-to-requirement`（壁打ち）が確定させた採番・per-要件要件定義・検討経緯を入力に、
PSK30 準拠の **一覧系**要件定義書群を `docs/requirements/` 配下に **直接生成**する（直接編集モデル）。

> 本スキルは新ワークフローの 2 段階方式の「生成段」。壁打ち・R###採番・per-要件 `要件定義_{要件ID}.md`・
> discussion-log・ADR は `issue-to-requirement`（オーケストレーター）が担う。本スキルは
> **system-wide な一覧系文書**（業務概要・要件一覧 等）の組み立てに専念する。
> 出力先は `docs/requirements/`（直接）。`specs/` には何も書かない。
> **機能ID（`{カテゴリ}-{3桁連番}`・スタック×API/画面/ジョブ単位）はここでは生成しない**（UI 工程 `/basic-design-gen` が要件IDを分解して採番する）。

## 入力形式
```
/requirement-doc-gen
案件キー: {案件キー}
SA issue-id: {issue_id}
対象要件ID: {R001 ...}   （省略時は今回の SA issue で採番した全要件）
```

## ドキュメント種別の前提（すべて一覧系・`_{機能ID}` サフィックスなし）

| ドキュメント | 種別 | 初回（ファイルなし） | 2 回目以降（ファイルあり） |
|---|---|---|---|
| 業務概要.md | プロダクト共通（固定） | テンプレート構造で新規生成 | 業務範囲の変更分のみ更新 |
| システム全体図.md | プロダクト共通（固定） | テンプレート構造で新規生成 | スタック変更分のみ更新 |
| システム化業務フロー.md | プロダクト共通（累積） | テンプレート構造で新規生成 | 新規フローセクションを追記 |
| 要件一覧.md | プロダクト共通（累積・**R###採番台帳の正本**） | テンプレート構造で新規生成 | 今回の要件行のみ追記 |
| コード定義書.md | プロダクト共通（累積） | テンプレート構造で新規生成 | 今回のコード定義のみ追記 |
| 画面レイアウト.md | プロダクト共通（累積） | テンプレート構造で新規生成 | 今回の画面セクションのみ追記 |
| ユースケース図.md | プロダクト共通（累積） | テンプレート構造で新規生成 | 今回の要件分のユースケース・関連のみ追記 |
| 画面遷移図.md | プロダクト共通（累積） | テンプレート構造で新規生成 | 今回の画面分の遷移のみ追記 |
| 帳票レイアウト.md | プロダクト共通（累積・該当時のみ） | テンプレート構造で新規生成 | 今回の帳票セクションのみ追記 |

> per-要件 `要件定義_{要件ID}.md` は `issue-to-requirement` が直接作成済み。本スキルでは生成しない（読込のみ）。

## 実行手順

### Step 1: 入力チェック
- [ ] `specs/{案件キー}/requirements/{issue_id}/discussion-log.md` が存在するか確認
- [ ] `docs/requirements/要件定義_{要件ID}.md`（対象要件分）が存在するか確認
- [ ] `docs/requirements/` ディレクトリが存在するか確認（なければ `mkdir -p docs/requirements`）

### Step 2: 必要ドキュメントの読み込み
- `specs/{案件キー}/requirements/{issue_id}/discussion-log.md` — 壁打ちサマリー・主要決定
- `docs/requirements/要件定義_{要件ID}.md`（対象要件分） — 確定済みの per-要件要件定義（目的/要求一覧/受け入れ条件/非機能/制約/除外）
- `specs/{案件キー}/requirements/{issue_id}/meta.md` — 影響スタック・対象要件ID
- `specs/{案件キー}/meta.md` — プロダクト名・R###採番表
- `docs/requirements/要件一覧.md` — **既存の採番（重複確認・最大番号確認）**
- `docs/glossary/business-terms.md`（存在する場合） — 業務用語
- `docs/architecture/stack-dependency.md`（存在する場合） — スタック構成
- `docs/architecture/overview.md` — **SA工程で確定済みのDB製品（技術スタック表「データベース」行）。システム全体図.md の DB 行に転記する（読み込み専用）**

### Step 3: シナリオ判定
`docs/requirements/業務概要.md` の存在を確認する。

| 状態 | シナリオ | 動作 |
|---|---|---|
| **存在しない** | **初回プロダクト生成** | テンプレート構造をベースに全ファイルを**新規作成** |
| **存在する** | **機能追加または修正** | 既存ファイルを読み、今回の機能に関係する差分のみ**追記・更新**（他機能の記述は削除しない） |

### Step 4: 各設計書の生成
各テンプレート（`docs/templates/30_要件定義/`）の構造を維持し、壁打ち成果（discussion-log・per-機能要件）を反映して生成する。

#### 業務概要.md
- **【初回】** プロダクト名（案件 meta から）・システム概要・業務フロー概要・利用者・権限・システム範囲・関連システム・用語定義を、discussion-log と per-機能要件から抽出して全セクション生成。
- **【追加/修正】** 変更が生じたセクションのみ更新（新規利用者・新規関連システム等の行を追加）。

#### システム全体図.md
- **【初回】** 工程issue meta の影響スタックをもとに Mermaid `graph TD` 図とシステムコンテキスト表を生成。外部システム連携があれば ExtSys ノードを追加。システムコンテキスト表の「DB」行は `docs/architecture/overview.md`（`issue-to-requirement` Step 1.5 で確定済み）の DB 製品名をそのまま転記する（本スキルでは DB 製品を再選定しない。`overview.md` がまだプレースホルダーの場合は `issue-to-requirement` Step 1.5 が未実施のため、先にそちらを完了させる）。
- **【追加/修正】** 新スタック・外部システム追加時のみ図と表を更新（DB 行は変更しない）。

#### システム化業務フロー.md
- **【初回】** discussion-log の業務フローを Mermaid `flowchart LR` スイムレーン図に変換。複数フローはセクション分け。
- **【追加/修正】** 今回追加・変更されるフローのセクションのみ追記・更新（既存フローには触れない）。

#### 要件一覧.md（**R001 単一連番・採番台帳の正本**）
- **【初回】** テンプレート構造（要件一覧表のみ・No./要件ID/要件名/備考）を生成。
- **【追加/修正】** **今回の SA issue で採番済みの要件行のみ**を追記する。既存行は変更しない。
- **採番規約（重要）**: 要件ID は **`R001`（単一3桁ゼロ埋め連番）**。業務要求単位で一連の `R###` を振る。**画面・帳票・処理といった機能種別はこの段階では決めない**（種別の確定は UI 工程 `/basic-design-gen` が `docs/base-design/機能一覧.md` で行う）。
  - 種別別2桁（`F01/R01/J01`）・画面ID `SCR001` は**使わない**（旧方式）。
  - 採番の実体は `issue-to-requirement` Step 5 が実施済み。本スキルは台帳への反映と整合確認を行う。
  - **機能ID（`{カテゴリ}-{3桁連番}`）はここでは採番しない**（UI 工程 `/basic-design-gen` が要件IDをスタック×API/画面/ジョブ単位に分解して採番する）。

#### コード定義書.md
- **【初回】** 区分コード・フラグ・ステータス値の定義があれば生成。なければ「現時点でコード定義はありません」と記載。
- **【追加/修正】** 今回追加されるコード定義のセクションのみ追記。既存定義には触れない。

#### 画面レイアウト.md
- **【初回】** per-要件要件定義・discussion-log の画面要求から、要件ID（`R###`）に紐づけて各画面セクションを生成。画面項目定義・バリデーション・ASCII レイアウトを含める（**UI 工程 `/basic-design-gen` で API レスポンスを参照して詳細化される**）。
- **【追加/修正】** 今回追加・変更される画面のセクションのみ追記・更新。既存画面には触れない。

#### ユースケース図.md
- **【初回】** アクター一覧・discussion-log のユースケース壁打ち結果から Mermaid `graph LR` 図とユースケース一覧表を生成（要件ID単位）。
- **【追加/修正】** 今回の要件分のアクター・ユースケース・関連のみ追記。既存ユースケースには触れない。

#### 画面遷移図.md
- **【初回】** 画面レイアウト.md の画面一覧と discussion-log の画面遷移壁打ち結果から Mermaid `flowchart TD` 図と遷移条件表を生成。
- **【追加/修正】** 今回追加・変更される画面の遷移のみ追記・更新。既存の遷移には触れない。

#### 帳票レイアウト.md（該当する場合のみ）
- 帳票・PDF・CSV・Excel の記述がある場合のみ生成/更新。
- **【初回】** 全帳票のセクションを生成（帳票も `R###` に紐づける）。**【追加/修正】** 今回分のセクションのみ。

### Step 5: ファイル書き込み
各ファイルを `docs/requirements/` に書き込む。

**注意事項:**
- プロダクト名・作成日（本日）を必ず記入する
- 推定・想定で記入した箇所には `> ⚠️ TODO: 要確認` を付与する
- Mermaid 図は必ず正しい構文で生成する
- 要件ID は `docs/requirements/要件一覧.md` の最大番号を確認し、`R###` 連番の整合を保つ

### Step 6: 完了報告
```
✅ 要件定義書群の生成が完了しました（工程1 SA・生成段）。

🆕 シナリオ: {初回プロダクト生成 / 要件追加・修正}
🔑 対象要件ID: {R### ...}

📁 更新したファイル（docs/requirements/）:
   {生成・追記したファイルの一覧（新規/追記 を明記）}

⚠️ 要確認事項:
   - `> ⚠️ TODO:` コメント箇所を確認・補完してください
   - 要件一覧.md の要件ID（R001 連番）が per-要件 要件定義・案件 meta 採番表と一致しているか確認してください
   - 画面レイアウト.md の項目定義は UI 工程 /basic-design-gen で詳細化されます
   - 画面遷移図.md の粗い遷移は UI 工程の画面状態遷移図で state レベルまで詳細化されます

📝 上記の生成物をご確認ください。修正が必要な場合は内容を教えてください。

🎯 次のアクション（確認後）:
   問題なければ、docs-to-pr.md の手順で SA 工程ゲート PR を作成してください
   （工程=SA・ブランチ feature/{案件キー}-sa・ベース feature/{案件キー}）。
   UI 工程で要件ID をスタック×API/画面/ジョブ単位の機能ID(`{カテゴリ}-{3桁連番}`)に分解します。
```

## 制約
- 🚫 `要件定義_{要件ID}.md`・discussion-log の内容を削除・変更しない（読込専用）
- 🚫 `specs/` 配下には書き込まない（成果物は `docs/requirements/` へ直接＝直接編集モデル）
- ✅ テンプレートのセクション構造・表の列定義を維持する
- ✅ **既存ファイルがある場合は今回の要件に関係する差分のみを追記・更新し、他要件・他issueの既存記述は絶対に削除しない**
- ✅ 要件ID は **`R001` 単一連番**（種別別2桁・画面IDは使わない）
- 🚫 機能ID（`{カテゴリ}-{3桁連番}`）は本スキルでは採番しない（UI 工程の責務）
- ✅ Mermaid 図は必ず構文が正しいものを生成する
- ✅ 不明な情報は `> ⚠️ TODO:` コメントで明示する
