# ブラウザキャッシュ制御（Reacter）

> 制約レベルの凡例は `rule-overview.md` を参照。

## 🚫 禁止 (NEVER)

- （該当なし）

## ⚠ 非推奨 (AVOID)

- （該当なし）

## ✅ 必須 (ALWAYS)

- [COM-06] ✅ **必須 (ALWAYS)**: ファイル名にハッシュ値が付かないコンテンツ（`index.html`、`/public` フォルダ配下の静的ファイル）は、サーバ上の資材変更に備えてブラウザにキャッシュされないよう、キャッシュ制御を行うこと。
- [COM-06] ✅ **必須 (ALWAYS)**: キャッシュ制御の方法はレスポンスヘッダーを用いる。

## ✨ 推奨 (PREFER)

- [COM-07] ✨ **推奨 (PREFER)**: HTTP 通信により静的ファイルを取得する場合、キャッシュ制御を行うこと。
  - 補足（✅必須 と ✨推奨 のスコープ差）: 上記 ✅必須 は「ハッシュ非付与で**配信される**資材（`index.html`・`/public`）をキャッシュさせない」配信側の制御。本 ✨推奨 は「アプリが HTTP で**取得する**静的ファイルのキャッシュ制御」を指す。対象が異なるため別分類で併記している（矛盾ではない）。

## 条件付き事項（一覧）

- [参考] `/src` 配下（`index.html` を除く js・css など）は、ビルド後のファイル名にハッシュ値（`index-[ハッシュ値].js` / `index-[ハッシュ値].css`）が付くため、キャッシュ制御は不要（キャッシュしてよい）。`index.html` からリンクされるため、`index.html` を更新すれば新しい js・css が使われる。
  - **条件成立時: 任意（既定挙動の説明）**
- [参考] `index.html` をキャッシュしないことで毎回サーバーへ取りに行き、リンク先の js・css はファイル名が変わっていなければキャッシュを使い、変わっていればサーバーへ取りに行く。
  - **条件成立時: 任意（仕組みの説明）**

## 参考・推奨実装パターン

- blank-template 利用時は、以下のキャッシュ制御レスポンスヘッダーを出力する。

    ```
    Cache-Control: no-cache, no-store, max-age=0, must-revalidate
    Pragma: no-cache
    Expires: 0
    ```
