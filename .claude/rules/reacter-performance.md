## ✨ 推奨 (PREFER)

- [STR-32] ✨ **推奨 (PREFER)**: 関数の定義をコンポーネント内で行う必要がない場合は、コンポーネント外で定義すること（関数の生成は一度だけになるため、`useCallback` を利用したメモ化が不要になる）。コンポーネント外で関数を定義可能な場合は、可能な限りコンポーネント外で定義すること。
  （根拠: `01.Reacterプログラミング/.github/instructions/reacter-blank-programming.instructions.md` §2.11、`reacter-docs-main/08.パフォーマンスチューニング/01.不要レンダリングの排除（メモ化）.md`）

## 条件付き事項（一覧）

- [参考] メモ化機能（`useMemo`・`memo`・`useCallback`）は併用可能であり、発生しているパフォーマンス問題やコンポーネントの構造に応じて使い分ける。
  - **条件成立時: 任意（状況依存の使い分け）**
  （根拠: `reacter-docs-main/08.パフォーマンスチューニング/01.不要レンダリングの排除（メモ化）.md`）
- [STR-33] コールバック関数を props に渡すケースでは、`memo` だけではメモ化が機能しない。この場合は `useCallback` で関数自体をメモ化する。
  - **条件成立時: ✅必須（コールバックを props に渡す場合）**
  （根拠: `reacter-docs-main/08.パフォーマンスチューニング/01.不要レンダリングの排除（メモ化）.md`）
- [参考] 変数だけを props に渡すケースでは、`memo` による対応だけで問題ない。
  - **条件成立時: 任意（説明）**
  （根拠: `reacter-docs-main/08.パフォーマンスチューニング/01.不要レンダリングの排除（メモ化）.md`）
- [STR-34] `lazy` はデフォルトエクスポートのみに対応しているため、コード分割対象のモジュールはデフォルトエクスポートが必要。
  - **条件成立時: ✅必須（コード分割対象はデフォルトエクスポートが必要）**
  （根拠: `reacter-docs-main/08.パフォーマンスチューニング/02.コード分割、遅延ロード.md`）
- [参考] React18（共通部品 v1.x.x）を使用している場合、`react-router` ではなく `react-router-dom` から import する。また `startTransition` でラップする `navigate` に `void` は不要。
  - **条件成立時: ✅必須（React18使用時の作法）**
  （根拠: `reacter-docs-main/08.パフォーマンスチューニング/02.コード分割、遅延ロード.md`、`reacter-docs-main/08.パフォーマンスチューニング/04.トランジションによるレンダリングの遅延.md`）
- [STR-31] メモ化の効果が見込めない場合はメモ化を行わないこと。メモ化は効果があるケースでのみ利用し、求めている効果が出ているか確認すること。効果があるケースは以下の通り。
    - props の変更による再レンダリングの可能性が低い場合
    - コンポーネント内の重い処理が、複数回実行しても同じ結果を返す場合
  - **条件成立時: ✅必須（メモ化を行う場合）**
  （根拠: `01.Reacterプログラミング/.github/instructions/reacter-blank-programming.instructions.md` §2.11、`reacter-docs-main/08.パフォーマンスチューニング/01.不要レンダリングの排除（メモ化）.md`）

## 参考・推奨実装パターン

### [参考] コード分割・遅延ロード（`React.lazy` / `Suspense`）

- SPA は初期アクセス時に全モジュールをダウンロードするため、規模が大きいほど初期ロードが長くなる。`lazy` を使い、モジュールが必要になった段階でダウンロードする。
- コード分割の単位は任意だが、機能のまとまりの単位（メニュー単位）が適切。`src/features` 配下に機能ごとのフォルダ（例: `home`・`item`）を作り、各フォルダ直下の `index.tsx` に機能内ルーティング定義を記載する。
- `lazy(() => import('フォルダパス'))` で遅延ロード対象を定義し、`<Suspense fallback={コンポーネント}>` で全体を囲んで遅延ロード中の表示コンポーネントを定義する。
- ネストした `<Routes>` を遅延ロードする場合、ルートの `path` は `/item/*` のように `*` が必要。
- 動作: 初回アクセス時に対象配下をダウンロードし、ダウンロード中は fallback を表示。2 回目以降は即座に表示する。

（根拠: `reacter-docs-main/08.パフォーマンスチューニング/02.コード分割、遅延ロード.md`）

### [参考] トランジションによるレンダリングの遅延（`startTransition`）

- `startTransition(コールバック関数)` の引数に設定したコールバックは「トランジション」（すぐ画面反映しなくてよい優先度の低い状態更新）として扱われる。
- ユーザー操作（入力・クリック）への再レンダリングは即時に行い、副作用による状態変化の結果の再レンダリングは非同期で処理して完了次第反映、という制御ができる。
- 画面表示に時間がかかる画面への `navigate` を `startTransition` でラップすると、取得処理完了までレンダリングを遅延し現在のページ表示のまま保つ（`startTransition` なしの場合は `Suspense` のフォールバックが表示される）。

（根拠: `reacter-docs-main/08.パフォーマンスチューニング/04.トランジションによるレンダリングの遅延.md`）
