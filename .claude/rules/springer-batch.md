# 18 バッチ設計

> 分類凡例: 🚫 禁止 / ⚠ 非推奨 / ✅ 必須 / ✨ 推奨 / 条件付き事項 / 参考・推奨実装パターン
> 関連: バッチは BS 層/DS 層の 2 層構成（[springer-architecture-layer.md](springer-architecture-layer.md) R-01-08）。

## 🚫 禁止 (NEVER)

### R-18-01 OS のスケジュール機能を使用しない
OS が提供するスケジュール機能を使用しない（ジョブはすべてジョブ管理ソフトウェアで一元管理する）。

## ⚠ 非推奨 (AVOID)

（なし）

## ✅ 必須 (ALWAYS)

### R-18-02 ジョブはジョブ管理ソフトウェアで一元管理する
ジョブはすべてジョブ管理ソフトウェアでスケジュールを一元管理する（R-18-01 の表裏）。

### R-18-03 1 ジョブ＝1 シェルスクリプトで構成する
1 つのジョブは必ず 1 つのシェルスクリプトで構成し、シェルスクリプトから業務処理を担う Java アプリケーション／コマンドを呼び出す。

### R-18-04 シェルスクリプトから呼び出す実行ファイルは 1 つにする
シェルスクリプトから呼び出される実行ファイルは必ず 1 つとし、複数ある場合はジョブを分割する。

### R-18-05 シェルスクリプトで戻り値を変換する
シェルスクリプトは、呼び出した Java アプリ／コマンドの実行結果を、呼び出し元ジョブが期待する戻り値に変換してジョブ管理ソフトウェア（エージェント）経由で返す。

### R-18-06 コマンド処理以外は Java アプリケーションで処理する
コマンド（OS/ミドルウェア）の処理以外はすべて Java アプリケーションで処理する（外部/内部 API 呼出・DB の CRUD・ファイル I/O）。

### R-18-07 リラン性を考慮して設計する
ジョブネット/ジョブは必ずリランを考慮しリカバリーできるよう設計する。リランの最小単位はジョブとし、失敗したジョブから再実行可能にする。各ジョブの役割を明確にし処理を適切に分割する（大きすぎる単位は不要な再処理を招く）。

### R-18-08 Java 実行時の例外を戻り値で検知できるよう設計する
ジョブ管理ソフトウェアから起動する Java 実行では、例外発生時に戻り値でエラーを検知できるよう設計し、シェルスクリプトで検知して適切な戻り値を返す。

### R-18-09 ジョブ実行にタイムアウトを設定する
ジョブ実行にはタイムアウト時間を設定し、想定外の長時間実行を検知できるようにする。

### R-18-10 イベント実行と競合する更新を避ける設計にする
イベント実行（HULFT 集信等）は随時行われるため、競合するリソースの更新を行わない設計にする。オンライン処理と競合する場合はジョブの処理を優先する。

## ✨ 推奨 (PREFER)

### R-18-11 ジョブの排他制御（リソース共有の回避）
ジョブ実行ではリソースの共有をできるだけ避ける（処理効率向上・再実行の複雑性排除）。競合する更新はジョブ管理ソフトウェアのスケジュールを考慮し競合が起きないよう設計する。

### R-18-12 ジョブの並行実行で処理時間を短縮する
排他制御・リソース使用量に問題が出ない範囲で、極力ジョブを並行実行するようジョブネットを設計する。

## 条件付き事項

### R-18-C1 オンライン処理と競合する更新はオンライン閉塞時間帯に実行する
競合が発生する設計を避けるのが原則だが、競合する更新を行う場合はオンライン閉塞時間帯にジョブを実行する。

### R-18-C2 トランザクション処理方式の選択
- 1 ジョブ 1 トランザクション: DB リソースを共有しない／共有してもロック影響が低い場合。異常終了時のロールバックが容易。大量データではロック長時間化等に注意。
- 1 ジョブ複数トランザクション: ロック影響が大きい場合。コミット単位は業務要件で個別検討し、リランをどの時点から行うか設計する。

### R-18-C3 コマンド／監視不可イベントの例外処理
コマンド実行は戻り値で確認できる場合はシェルで確認、できない場合は個別対応。ジョブ管理ソフトウェアで直接監視できないイベント（HULFT 集信等）は個別対応し、確実にオペレーターへ通知が届くようにする。

## 参考・推奨実装パターン

- バッチ構成要素: ジョブ管理ソフトウェア（マネージャー/エージェント）・スケジュール機能・ジョブネット・ジョブ・シェルスクリプト・Java アプリ・コマンド（OS/ミドルウェア）。
- コマンド例: `cp`/`sed`（OS）、HULFT 集配信・PostgreSQL `COPY`（ミドルウェア）。
- Java アプリは Springer 提供テンプレート `springer-blank-batch` を元に実装する。
- リカバリーはジョブ管理ソフトウェアの管理コンソールからジョブを再実行する。
